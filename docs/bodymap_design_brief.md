# 체크당 — 2D 바디맵 디자인 의뢰

> 본 의뢰는 별도 STEP. `docs/design_brief.md` (전체 화면 디자인 의뢰) 에서 명시적으로 **제외**했던 "BodyMap 의 인체 모형 그림 자체" 를 다루는 후속 작업입니다.

## 0. 앱 한 줄 소개

**체크당 (Check-Dang)** — 한국의 당뇨 환자가 매일 혈당·운동·식사·수면을 기록하고, 통증 패턴까지 AI 로 분석받는 헬스케어 Android 앱. 본 바디맵은 사용자가 **통증 부위를 인체 그림에서 직접 터치**해서 기록하는 화면에 사용됩니다.

## 1. 현재 구현 상태 (= 교체 대상)

현재는 인체가 아닌 **회색 사각형 박스의 모자이크** 입니다. 와이어프레임 수준이며, "여기가 머리/가슴/팔"임을 사각형 위치로만 짐작하는 상태.

```
정면(현재)                          후면(현재)
┌──────────────┐                  ┌──────────────┐
│   [□머리□]    │                  │   [□머리□]    │
│   [□목□]      │                  │   [□목□]      │
│ [□][□가슴□][□] │ ← 양쪽 어깨+가슴   │ [□] [□등 위□] [□] │
│ [□팔][복부][팔□] │                  │ [□] [□허리□]  [□] │
│   [골][골]    │                  │              │
│   [허][허]    │                  │   [허][허]    │
│   [무][무]    │                  │              │
│   [정][정]    │                  │   [정][정]    │
└──────────────┘                  └──────────────┘
```

- 파일: `app/src/main/java/com/checkdang/app/ui/bodymap/BodyMapView.kt`
- 구현 방식: `Canvas.drawRoundRect()` 로 각 부위를 회색 둥근 사각형 그림 + 선택 시 brand_green 하이라이트
- 좌표계: viewBox **200 × 400** (1:2 비율), `nRect(l, t, r, b)` 로 정규화
- 인체 일러스트 부재 → 사용자가 "어디를 터치해야 하는지" 직관적으로 알기 어려움

## 2. 의뢰 목적 — 무엇을 만들 것인가

**해부학적으로 사실적이지만 친근한 톤의 2D 인체 일러스트** 두 장 (정면 / 후면) + 각 부위별 터치 영역 정의. 결과물은 Android `VectorDrawable` 로 변환 가능해야 하며, 현재 `BodyMapView.kt` 의 `frontRegions` / `backRegions` 맵을 새 좌표로 교체합니다.

### 2.1 그려야 할 부위 — 총 21개

**정면 (16개, BodyView.FRONT)**
| BodyPart enum | 한글 라벨 |
|---|---|
| HEAD | 머리 |
| NECK_FRONT | 목 (앞) |
| LEFT_SHOULDER_FRONT | 왼쪽 어깨 |
| RIGHT_SHOULDER_FRONT | 오른쪽 어깨 |
| CHEST | 가슴 |
| LEFT_ARM_FRONT | 왼팔 |
| RIGHT_ARM_FRONT | 오른팔 |
| ABDOMEN | 복부 |
| LEFT_HIP_FRONT | 왼쪽 골반 |
| RIGHT_HIP_FRONT | 오른쪽 골반 |
| LEFT_THIGH_FRONT | 왼쪽 허벅지 |
| RIGHT_THIGH_FRONT | 오른쪽 허벅지 |
| LEFT_KNEE | 왼쪽 무릎 |
| RIGHT_KNEE | 오른쪽 무릎 |
| LEFT_SHIN | 왼쪽 정강이 |
| RIGHT_SHIN | 오른쪽 정강이 |

**후면 (12개, BodyView.BACK)**
| BodyPart enum | 한글 라벨 |
|---|---|
| HEAD | 머리 (정면과 공유) |
| NECK_BACK | 목 (뒤) |
| LEFT_SHOULDER_BACK | 왼쪽 어깨 (뒤) |
| RIGHT_SHOULDER_BACK | 오른쪽 어깨 (뒤) |
| UPPER_BACK | 등 위 |
| LOWER_BACK | 허리 |
| LEFT_ARM_FRONT | 왼팔 (후면에서도 동일 enum 재사용 — 의도된 단순화) |
| RIGHT_ARM_FRONT | 오른팔 |
| LEFT_THIGH_FRONT | 왼쪽 허벅지 |
| RIGHT_THIGH_FRONT | 오른쪽 허벅지 |
| LEFT_SHIN | 왼쪽 정강이 |
| RIGHT_SHIN | 오른쪽 정강이 |

> **주의**: 후면에는 무릎/골반/가슴/복부 enum 이 없습니다. 다리 후면도 정면 enum (`*_FRONT`) 을 재사용. **enum 자체는 변경하지 않습니다.** 디자인은 이 부위 분할을 그대로 따라야 합니다.

### 2.2 좌측/우측의 의미

화면을 보는 **사용자 관점이 아니라 인체 자신의 좌/우**를 따릅니다 (의학적 관례).
즉 정면에서 인체의 "왼팔" 은 화면상 **오른쪽** 에 표시됩니다. 후면도 마찬가지(다만 좌우가 화면상으로 뒤집힘).

## 3. 디자인 요건

### 3.1 시각 톤
- **친근함 + 의학적 신뢰감의 균형** — 의료기기/임상 차트처럼 차가워 보이지 않게. 본 앱은 의료기기가 아님 (참고용 정보)
- **성별 중립 (genderless)** — 환자가 남녀노소 (30~70대). 특정 성별로 보이지 않도록 단순화된 실루엣
- **얼굴 표정 없음** — 머리는 윤곽만. 표정은 통증 인상을 왜곡시킴
- **한국 헬스케어 앱 톤** — 토스/카카오 헬스 수준의 깔끔함. 너무 만화체도, 너무 임상체도 X
- **시니어 친화** — 부위 경계가 직관적으로 구분되어 명확해야 함

### 3.2 컬러 토큰 (현 시스템 준수)
| 용도 | HEX | 비고 |
|---|---|---|
| 인체 채움 (기본) | `#D0D0D0` 또는 더 따뜻한 톤 제안 환영 | 현재값 |
| 인체 윤곽선 | `#A0A0A0` | 현재값 |
| 선택 하이라이트 채움 | `#4CAF50` @ alpha 100/255 | brand_green |
| 선택 하이라이트 윤곽 | `#4CAF50` @ alpha 200/255, strokeWidth 4f | |
| 부위 경계선 (제안) | 보조 그레이 — 너무 강하면 와이어프레임 회귀 | 신규 토큰 제안 가능 |
| 배경 | `#FFFFFF` (카드 안에 놓임) | 카드 padding 16dp |

### 3.3 기술 제약 — **반드시 준수**
- **출력**: SVG 2장 (front, back). `viewBox="0 0 200 400"` 기준 (BodyMapView 와 일치)
- **VectorDrawable 변환 가능해야 함** — Android Studio "Vector Asset" 임포트로 깨지지 않을 것
  - `<path>`, `<rect>`, `<circle>`, `<ellipse>` OK
  - `<filter>`, `<mask>`, `<clipPath>` 는 변환 시 종종 깨짐 — 사용 최소화
  - `<linearGradient>` 는 가능하나 단순한 것만 (2~3 stop)
  - 외부 폰트/이미지 임베드 금지
- **Lottie / Rive / 애니메이션 금지** (정적 SVG 만)
- **라이트 모드 전용** — 다크모드 변형 불요

### 3.4 터치 영역 (히트 박스) 요건
인체 일러스트는 시각용이고, **터치 판정용 영역은 별도로 정의**해야 합니다. 현재 코드:

```kotlin
private val frontRegions: Map<BodyPart, RectF> = mapOf(
    BodyPart.HEAD               to nRect(74, 10, 126, 66),
    BodyPart.LEFT_SHOULDER_FRONT to nRect(30, 82, 60, 116),
    // ... viewBox 200x400 기준 좌표
)
```

→ 디자인 결과물에는 **각 부위별 히트 박스 좌표 (RectF 또는 Path) 를 별도 표** 로 제공해 주세요. 형식 예시:

```
BodyPart.HEAD               → rect(74, 10, 126, 66)
BodyPart.LEFT_SHOULDER_FRONT → rect(30, 82, 60, 116)
...
```

또는 더 정밀하게 **Path 기반 히트 테스트** 가 가능하다면 path SVG 도 환영 — `Region.setPath()` 로 Android 에서 처리 가능.

**히트 영역 최소 크기**: 화면 표시 시 약 **44 × 44 dp 이상** 권장 (시니어 친화). 정강이/목처럼 좁은 부위는 시각적 부위보다 히트 박스를 약간 확장 OK.

### 3.5 좌우 대칭 부위 처리
- 좌/우 어깨, 팔, 골반, 허벅지, 무릎, 정강이는 **세로축 대칭** 으로 동일 형상
- 히트 박스 경계가 인체 중앙선과 정확히 일치하지 않아도 됨 (사실적 인체는 비대칭 부위 존재)
- 단 좌/우 라벨은 사용자가 헷갈리지 않게 분리감 있어야 함

## 4. 선택지가 있는 디자인 결정 — 권장안 + 이유 함께 제안 부탁

| # | 결정 항목 | 선택지 | 비고 |
|---|---|---|---|
| Q1 | 인체 스타일 | (a) 해부도식 (의학 일러스트) / (b) 추상 픽토그램 / (c) 그 중간 (단순화된 사실적 인체) | (c) 권장하나 의견 받습니다 |
| Q2 | 머리 표현 | (a) 단순 원 / (b) 얼굴 윤곽 (귀/턱선) / (c) 측면 비율 머리 | 표정/이목구비 없음 전제 |
| Q3 | 부위 경계 가시화 | (a) 부위별 약한 윤곽선 / (b) 미세한 색 차이 / (c) 평소 안 보이고 호버/선택 시만 | 와이어프레임 회귀 방지 |
| Q4 | 손/발 디테일 | (a) 단순화 / (b) 윤곽 표현 | 손/발은 enum 부위 아님. 시각 균형만 |
| Q5 | 의복 표현 | (a) 나신 실루엣 / (b) 짧은 속옷 라인 | 한국 정서 고려 — (b) 안전 |

## 5. 산출물 (요청 형식)

1. **디자인 컨셉 한 단락** — 본 바디맵에 적용한 톤/방향성 요약
2. **front.svg, back.svg** — `viewBox="0 0 200 400"`, VectorDrawable 변환 검증 완료된 코드
3. **히트 박스 좌표 표** — 21개 BodyPart 각각의 RectF (또는 Path)
4. **컬러 토큰** — 새로 추가가 필요한 보조 그레이/액센트가 있다면 HEX 로
5. **선택/비선택 상태 미리보기** — 예: "왼쪽 무릎 선택" 시 어떻게 보이는지 1컷
6. **Q1~Q5 결정 사항** — 어떤 옵션을 택했고 왜인지

## 6. 명시적으로 **하지 않을 것**

- 부위 추가/삭제 — BodyPart enum 은 고정 (변경 시 ViewModel/Adapter 까지 전부 영향)
- 3D / 회전 가능한 인체 — 정면/후면 2장만
- 애니메이션 (회전, 펄스, 호흡) — 정적만
- 다국어/RTL — 한국어 라벨만
- 다크모드 변형

## 7. 자가 검증 체크리스트 (디자인 측에서 확인 부탁)

- [ ] `viewBox="0 0 200 400"` 사용
- [ ] front 16개 / back 12개 부위 모두 시각적으로 식별 가능
- [ ] Android Studio "Convert SVG to Vector Drawable" 통과 (경고/오류 없음)
- [ ] 인체의 좌/우 = 인체 자신 기준 (의학적 관례)
- [ ] 좁은 부위(목, 정강이)도 히트 박스 44×44dp 이상 (200×400 viewBox 에서 약 28×14 단위 이상)
- [ ] 히트 박스 표가 21개 BodyPart 모두 커버
- [ ] 표정/성별 표현 없음
- [ ] linearGradient 외 복잡 SVG 필터 미사용
- [ ] brand_green (`#4CAF50`) 하이라이트 색 호환
