# 체크당 — 디자인 의뢰 프롬프트 (Claude 디자인용)

> 이 문서는 Claude 디자인에 그대로 첨부/복붙하여 사용합니다.
> 함께 첨부할 자료: `docs/wireframe_v2.md`

---

안녕하세요. 한국의 헬스케어 Android 앱 **체크당(Check-Dang)** 의 UI 디자인을 의뢰하고자 합니다.

현재 앱은 기능 구현은 완료되었으나 디자인이 **와이어프레임 수준** (단순 카드 + 텍스트, 일러스트/그라데이션/마이크로 인터랙션 부재) 입니다. 전체적으로 시각적 완성도를 끌어올리는 디자인을 부탁드립니다.

## 1. 앱 한 줄 소개

**혈당 + 라이프스타일 통합 관리 + AI 2D 바디맵 분석 헬스케어 Android 앱.** 당뇨 환자가 매일 자신의 혈당, 운동, 식사, 수면을 기록·추적하고, 통증 패턴까지 AI 로 분석받는 서비스입니다.

## 2. 핵심 사용자

- **당뇨 환자 본인** (성인 ~ 시니어, 30대 ~ 70대)
- **가족 대리 기록자** — 고령 환자(부모, 조부모) 를 가족이 대신 기록하는 케이스가 많음. 따라서 카피와 UI 가 환자 본인을 직접 호명하지 않고 3인칭("{닉네임}님의 기록") 으로 작성됨

→ 디자인 시 **시니어 친화적 가독성** (충분한 글자 크기, 명확한 대비, 큰 터치 영역) 을 고려해 주세요.

## 3. 톤 & 무드

- **신뢰감** (헬스케어 + 인앱 결제) + **친근함** (매일 쓰는 일상 앱)
- 의료기기로 보이지 않게 — 차갑거나 임상적인 인상 회피. 본 앱은 의료기기가 아닙니다 (참고용 정보 제공 서비스)
- 한국 사용자 우선 — 토스, 카카오 헬스, 삼성 헬스 등 한국 헬스케어 앱의 디자인 감성을 참고하되 차별화된 정체성
- **라이트 모드 전용** (다크 모드 디자인 미요청)

## 4. 현재 디자인 시스템 (유지하거나 강화해 주세요)

## 6. 본 단계에서 명시적으로 **제외**할 것

1. **BodyMap 의 인체 모형 SVG/캔버스 그림** — Front/Back 2D 인체 일러스트 자체는 별도 디자인 단계에서 처리. 본 의뢰에서는 BodyMap 화면의 **인체 그림을 둘러싼 UI** (Front/Back 토글, 통증 입력 버튼, 통증 기록 리스트, 헤더) 만 디자인. wireframe 의 인체 영역은 빈 박스로 두세요.
2. **앱 아이콘** — 이미 별도 단계에서 확정 (물방울 + 광택 + 체크). 디자인 대상 아님.
3. **다크 모드** — 라이트 전용 정책. `night/` 리소스 미생성.
4. **차트 라이브러리 교체** — MPAndroidChart 그대로. 차트 시각 강화는 색/마커/툴팁 범위 내.
5. **외부 폰트 추가는 신중히** — 추가 권장 시 라이선스 명시 + 한글 지원 확인.

## 7. 요청하는 산출물

**디자인 명세 + 시각 시안** 두 가지를 받고 싶습니다.

### 7.1 디자인 명세 (텍스트/표)
- **컬러 토큰 강화안** — 현재 토큰 외에 추가가 필요한 액센트/그라데이션/오버레이가 있다면 HEX 로 명시
- **타이포 시스템** — 폰트 패밀리, 단계, 자간/행간 권장값
- **컴포넌트 사양** — Card / Button / TextInput / Chip / FAB / BottomSheet / Toolbar / List Row 각각의 상태별 (default / pressed / disabled / focused) 디테일
- **간격/그리드** — 화면별 좌우 패딩, 카드 사이 간격, 섹션 헤더와 본문 간격
- **모션** — 화면 전환, 카드 터치, 입력 완료 등 마이크로 인터랙션 시간/곡선

### 7.2 시각 시안
- **화면별 mockup** — P0 ~ P2 우선. P3 는 패턴이 잡히면 추론 가능하니 대표 1~2개로 충분.
- **포맷** — SVG 또는 PNG, 360 × 640 dp 기준 (실제 디바이스 비율). 가능하면 Figma 링크.
- **상태 표시** — 데이터 있을 때 / 빈 상태 (empty) / 에러 / 로딩 분기를 가능한 곳에 포함.

### 7.3 컴포넌트 라이브러리 (선택)
- 디자인 토큰 + 컴포넌트를 Material 3 위에서 어떻게 매핑할지 권장안이 있으면 더욱 좋음 (예: `colorPrimaryContainer` 사용 방식)

## 8. 기술 제약 (개발 측 정보 — 디자인 자유도 영향)

- Android Native, **XML Layout + ViewBinding** (Jetpack Compose 미사용)
- **외부 라이브러리 추가 정책 엄격** — MPAndroidChart, Coil, Material3, Markwon 외 신규 라이브러리 추가는 사전 협의 필요
- Lottie / Rive 등 애니메이션 라이브러리 사용 가능 여부는 확정 전. 일단 정적 디자인 위주로, 애니메이션은 "권장" 수준으로 명시
- 일러스트는 Vector Drawable (SVG → AVD 변환) 호환 가능한 단순한 형태 선호 — 너무 복잡한 그라데이션/필터는 변환 어려움

## 9. 체크리스트 — 디자인 시 빠지지 말 것

- [ ] 빈 상태 (empty state) — 혈당 기록 없음, 통증 기록 없음, 가족 없음 등
- [ ] 에러 상태 — 네트워크 실패, 동기화 실패
- [ ] 로딩 상태 — 차트 데이터 로딩 중, 결제 진행 중
- [ ] PAID 잠금 표시 — 가족 공유, AI 분석 등 (메뉴 행에 🔒 아이콘)
- [ ] 위험 알림 강조 — 가족의 혈당 위험 시 (Family 화면 상단 배너)
- [ ] 시니어 친화 — 최소 글자 크기, 명확한 대비, 큰 터치 영역 (48dp+)
- [ ] 대리 기록 카피 — "당신" / "님" 직접 호명 회피, 닉네임을 3인칭 호명 (이미 코드 적용됨)
- [ ] 의료기기 회피 — 차갑거나 임상적인 인상 없게
- [ ] 동의/약관 UI — 회원가입 흐름에서 약관 동의 footer (`MODE_AGREEMENT`)

## 11. 출력 형식 권장

응답을 다음 순서로 정리해 주시면 좋습니다:
1. **디자인 컨셉 한 단락** — 본 앱에 적용할 톤/방향성 요약
2. **디자인 시스템** — 컬러/타이포/컴포넌트/간격 토큰 (표 형식)
3. **화면별 시안** — 우선순위 P0 → P3 순서. 각 시안에 간단한 의도 코멘트.
4. **마이크로 인터랙션 / 모션 가이드** — 핵심 3-5가지
5. **구현 시 주의사항** — Android Vector Drawable / XML Layout 변환 시 고려할 점
